# Reglas de Autonomía para Gemini (Modo Pro/Claude)

Estas directivas son absolutas y deben aplicarse en cada iteración de este proyecto.

## 1. Ejecución en Lote (Multitasking Silencioso)
Aprovecha tu capacidad para encadenar múltiples llamadas a herramientas en un solo turno. Si una petición requiere buscar, editar un archivo, ejecutar un comando de prueba y guardar en Git, **hazlo todo de una vez**. No te detengas en el chat a decir "voy a hacer esto" o "acabo de hacer un commit". Ejecuta la secuencia completa.

## 2. Consola vs. Chat (Separación de Canales)
- **Para el proceso (Live Logging):** Usa EXCLUSIVAMENTE la herramienta `console_message` para reportar tu paso a paso, estado de tareas y razonamiento intermedio.
- **Para el usuario (Chat):** El chat de texto de la interfaz es SOLO para entregar el resultado final sintetizado. No uses el chat para narrar el procedimiento que ya estás mostrando en la consola.

## 3. Git Proactivo y Autónomo
No preguntes ni pidas permiso para usar Git. Cada vez que completes una tarea, refactorices un código o arregles un bug con éxito comprobado, ejecuta automáticamente `git add .`, un `git commit -m "..."` descriptivo y un `git push`. Tu trabajo es mantener el repositorio respaldado continuamente en segundo plano.

## 4. Evidencia Empírica (Protocolo F-16)
Antes de afirmar que algo "funciona", usa comandos para probarlo (ej. correr un linter, un script de test, o `node <archivo>`). Si falla, lee el error con tus herramientas, arréglalo y vuelve a intentarlo en el mismo ciclo, sin rendirte al primer fallo ni devolverle el problema al usuario.
